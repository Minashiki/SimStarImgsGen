# M6 质量评估与可视化

M6 是读取已落盘序列的离线工具。已有生成、标签、存储算法及版本不变，M5 冻结报告和生产目录不改写。新增功能没有改变相同种子的仿真数值输出，不递增已有算法版本。

## 使用

所有命令从仓库根目录启动，使用 D12 环境：

```powershell
conda run -n genstarimg --no-capture-output python -m starsim.visualize .tmp/m5_production_v023/seq_000000 artifacts/m6/preview --mode union
conda run -n genstarimg --no-capture-output python -m starsim.visualize .tmp/m5_production_v023/seq_000000 artifacts/m6/preview --mode reference
conda run -n genstarimg --no-capture-output python -m starsim.qa_report .tmp/m5_production_v023 artifacts/m6 --assert-thresholds
```

`visualize` 支持 `native`、`reference`（原参考帧大小）和 `union`（元数据中的参考系并集画布）。逐帧 PNG 和 GIF 采用相同的首帧灰度拉伸范围；逆单应插值生成图像，标签用同一个正向单应。预览保持半像素坐标约定，默认最长边 768 像素。青/绿/橙对应星、点目标、条纹；圆为 labeled，叉为 ignore，紫色为传感器热像素位置。条纹同时绘制真实端点。静态星在配准后固定，动目标保留参考系轨迹，传感器缺陷随相机运动反向移动。预览和图表不跟踪，保留生成代码。

`qa_report` 接受单序列目录或包含 `seq_*` 的数据集目录，输出 JSON 与四张图：速度、星等和 SNR 直方图；热像素/动目标 SNR 对比；阈值可分性累计分布；设计/实测档位、类别数量和 ignore 比例。JSON 还保留逐帧图外有通量源数、never_full 数、类别比例、档位交叉计数，以及每条目标观测的阈值、核心召回率、背景总像素数和虚警数。图外有通量的动目标也进入实验；无通量记录仍进入源数统计。

## 开工决策与统计口径

- 按计划放开 `scipy.stats` 确定性导入与调用；继续全面禁止 `.rvs()`，禁止 `bootstrap`、`permutation_test`、`monte_carlo_test`、`qmc`，包括简单别名、字面量动态导入和 `getattr`。不放开星号导入。扫描器仍以防无意误用为边界，不保证识别任意动态 Python。
- 用户确认采用 **2 + A**：整帧统计，排除所有真实源实际渲染 stamp 的闭区间；保留热像素、死像素、宇宙线等缺陷。核心召回率至少 50% 时，背景虚警像素不超过 **10** 判为可分。固定像素上限不随 4096² 生产帧面积折算。可用 `--max-false-positives` 显式调整，记录在报告中。
- 核心定义为该目标独立、无噪声、传感器响应前 stamp 内不低于其入图峰值 50% 的像素。使用冻结的 PSF 像素积分和曝光半径重建，并核对重建 box 与落盘 box 一致；核心定义不读取噪声图。截断目标按可见核心统计。
- 在原始 uint16 ADU 图上应用全帧标量阈值 `image >= threshold`，不做背景平坦化或缺陷去除。取保留至少半数核心像素的最高整数阈值（有序统计量，等价于完整扫描），平局像素全部计入。背景的 65536 档计数提供精确虚警数，不用抽样或高斯尾概率代替实测。
- 比例的统计单位是 **target-frame observation**，按设计档位分组；同一目标不同帧分别计数，不声称是独立抽样置信区间。缺少 ultra 或 bright 观测不能通过验收。`--assert-thresholds` 在 ultra 不可分率低于 90% 或 bright 可分率低于 99% 时返回退出码 1，报告和图仍保存。
- 相机速度来自元数据，目标速度为相邻参考系真实中心的距离，单位 px/frame。源数、星等、SNR、设计/实测档位均包含稀疏表中的全部记录，不只统计 labeled。
- 动目标 SNR 沿用稀疏表的无噪声自身峰值 / 局部背景标准差。热像素 nominal SNR 使用元数据中逐帧 RTS 状态选出的真实电平 / 参考背景标准差（截断前）；另存实际 FITS 热像素减去 7×7 邻域中位数的电子数 / 参考标准差。二者的分母口径及饱和、邻近源影响不同，图例和 JSON 明示，不能将对比图解读为统一噪声估计器的校准实验。

## 验证与当前结果

`tests/test_m6_qa.py` 覆盖确定性接口放行与随机接口拦截、阈值平局与最高阈值、空档位、配准的三个运动方向、投影逆变换和半像素缩放；小型落盘序列端到端运行统计与三种叠加模式，并核对全部输入文件哈希不变。

测试记录见 `artifacts/m6/verification.json`：当前收集 617 项，排除 9 项 slow，608 项快速测试全部获得通过记录。首次快速运行在 520 项通过后遇到 Windows 沙箱命名管道 `WinError 5`，保留其错误记录；剩余 88 项脱离沙箱运行全部通过。合并 JUnit 的通过用例身份与重新收集的 608 项集合一致；另有随机扫描器与 M6 专项 128 项通过。这是未提交实现的分段验证记录，不作为 D86 的正式冻结证据。

`artifacts/m6/qa_report.json` 使用冻结 M5 的 `.tmp/m5_production_v023` 作为离线评估输入：10 条序列、100 帧、4056 个有通量动目标观测。按上述原始 ADU、保留缺陷、固定 10 像素口径：ultra 967 项的不可分率 100%；bright 2208 项的可分率约 5.16%，未达到 99%。因此 **M6 工具已实现，阈值可分性验收未通过，M6 不宣布冻结**。报告如实保留失败；若后续改用背景归一化、缺陷屏蔽或调整生成配置，须先另定口径，不能混用这些结果。

可选 astrometry.net 盲解算未执行，未向外部服务上传数据。
